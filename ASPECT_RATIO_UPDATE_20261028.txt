CAUSE AND HISTORICAL EVIDENCE
The two audited problem jobs used an empty 1600 x 1000 workspace and three
global reference images. Asun selected size=1536x1024 from that unused canvas,
despite the user's 9:16 prompt and a 2160x3840 portrait Blender reference.
The generated instruction wrapper also told the model to keep that canvas's
aspect. The wrong orientation was already in the actual outgoing API request.
The saved PNGs are 1536x1024 (3:2 landscape, not 16:9). Input reference bytes
and dimensions were intact; no output crop/stretch or download conversion
caused this issue. Evidence: qa/portrait-output/history-audit.json.

IMPLEMENTED
- Aspect Ratio sits beside Quality under Image model. The initial preferred
  ratio is 9:16, remembered locally after an explicit choice. Saved projects,
  variants, workflow tabs and frozen job snapshots keep their own setting.
- Only verified, currently valid model/source choices are selectable. Switching
  to a model that cannot support the saved ratio leaves an explicit unsupported
  marker and blocks Generate until a supported choice is made. No substitution.
- The resolved size is sent through the OpenAI Images API size parameter in
  both JSON /images/generations and multipart /images/edits requests. Width,
  height or aspect_ratio fields unsupported by this integration are not sent.
- References cannot silently override an explicit generation ratio. An explicit
  MAIN/blockout lock with a conflicting ratio produces a visible error instead.
  Match source is a deliberate choice, and only appears when exactly supported.
- Requested pixels and ratio are shown before generation. Result details and
  history show actual encoded image dimensions and the calculated ratio.
- Saved output bytes are inspected and compared to the requested size. Wrong
  orientation, same-aspect wrong resolution, and one-pixel differences are
  flagged clearly. Current provider docs specify no output-rounding allowance;
  the multiple-of-16 input rule is not treated as an output tolerance.
- Previews retain proportions, including full-resolution zoom/inspection.
  Downloads preserve the original returned file bytes. There is no automatic
  crop, stretch, padding, upscaling, or retry to disguise an output mismatch.
- Selected-area edits override the general generation preference visibly with
  Keep edit canvas. Composition, annotation guide and selection masks use the
  same exact native canvas grid. The preferred generation ratio is unchanged.
  Masks stay standalone when many appearance references are packed into boards.
- If native edit dimensions are unsupported, generation stops with an explicit
  explanation. For example, 1080x1920 cannot be sent unchanged to Sunburst
  because 1080 is not a multiple of 16. No silent rounding or resizing occurs.
  Larger supported sizes above 3,686,400 pixels are marked experimental.
- Existing quality defaults and explicit user quality settings are unchanged.
  Retired GPT Image 1 is unavailable rather than silently replaced.

VERIFIED CAPABILITIES IN THE CURRENT DESKTOP OPENAI INTEGRATION
Sunburst (gpt-image-2.5-sunburst), Flare (gpt-image-2.5-flare), GPT Image 2:
  9:16 = 864x1536; 16:9 = 1536x864; 1:1 = 1024x1024;
  2:3 = 1024x1536; 3:2 = 1536x1024.
  Match source can use other exact legal ratios. Custom dimensions require
  multiples of 16, each side at most 3840, aspect from 1:3 through 3:1,
  and 655,360 through 8,294,400 total pixels.
GPT Image 1.5 and GPT Image 1 Mini:
  1:1 = 1024x1024; 2:3 = 1024x1536; 3:2 = 1536x1024.
  No exact 9:16 or 16:9. Their 2:3 portrait output is labelled honestly.
No other provider's capabilities are inferred from these OpenAI model rules.
