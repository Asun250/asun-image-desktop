ASUN IMG DESKTOP — PORTRAIT OUTPUT FIX — 2026-10-28

Confirmed cause
The latest two image jobs, 806ca387-a078-4d73-b690-39a5dc5f9167 and
da3e6d49 (full ID in qa/portrait-output/history-audit.json), had no canvas
layers. Their first reference was a 2160 x 3840 portrait Blender image.
The old request builder selected 1536x1024 from the empty 1600x1000 working
canvas and also told the model to retain that canvas aspect. Prompt text
requesting 9:16 did not change the API size parameter.

The actual saved PNGs were 1536 x 1024 (3:2 landscape, not 16:9). Their
original reference pixels and hashes were intact. The application did not
crop or resize provider outputs; it saved decoded PNG bytes directly.

Fix
- Output format beside Quality exposes Match source, 9:16, 16:9, 2:3, 3:2
  and 1:1, with the exact requested pixels and framing source visible.
- Match source uses an explicitly locked original MAIN/blockout first,
  otherwise the actual composition canvas, otherwise the first unlinked
  global reference. An empty default canvas no longer overrides that photo.
- The output choice is project-local and survives Save/Open, Undo/Redo,
  variants, workflow tabs and the saved source used by Redo.
- Sunburst, Flare and GPT Image 2 use supported exact-aspect dimensions.
  Exact 9:16 requests 864x1536. A portrait 2:3 requests 1024x1536.
  Unsupported sizes fail visibly with supported alternatives; no substitution.
- The API receives size=WIDTHxHEIGHT. No separate width/height/aspect_ratio
  parameter is sent. Selected model and quality are preserved.
- Generated framing instructions state the actual API output dimensions.
  The empty-canvas framing instruction is removed for reference-only work.
- Encoded output pixels are checked against the requested size. A mismatch
  is shown in the result/history/queue and the raw output remains untouched.
  Reviewed generations stop before a paid Astra call on a known mismatch.
  Neither cropping/stretching nor an automatic size-correction retry is used.

Reference image handling
Original reference images remain original bytes. Optional canvas, annotation
and mask previews retain proportions with a 2600px maximum long edge (integer
pixel rounding). Existing labeled reference-board packing for large sets is
unchanged. It does not determine the output size.
